# Fold 14 v10：下一步改善的第一性原理分析

本次重新讀取完整 v10 曲線、全部候選更新與 163 日精確帳戶，並用現行搜尋程式
重現一個可手算的反例。最優先的工作是補齊候選搜尋、定位相同參數的 train/eval
差異，再確認跨期間的超額報酬。尚未啟動新訓練，也沒有修改訓練器、交易規則、
checkpoint、v10 設定或原始結果。

- 對象：`artifacts/markets/tw_futures_v8_margin_verified_2011_capital100m_tx_front_roll_benchmark_risk_v10`
- 訓練 2011–2024，驗證 2025；研究測試 2026-01-02–2026-09-04，共 163 日。
- 工具：[`scripts/analyze_tw_futures_policy_refinement.py`](../scripts/analyze_tw_futures_policy_refinement.py)
- 證據：`artifacts/analysis/tw_futures_v10_refinement_20260928/analysis.json`；附全部逐日、
  逐月、逐 epoch、逐候選 CSV 及來源 SHA-256。
- 2026 已被研究使用。本分析不把它重新命名成未看過的樣本。

## 1. 先區分目標：成長、波動、回撤不是同一個量

令真實淨值為 E，日 log return 為 r，現有目標為：

\[
L(\theta)=-\frac{252}{T}\sum_t r_t(\theta),\qquad
r_t=\log(E_t/E_{t-1}).
\]

Sharpe 為 `sqrt(252) * mean(r) / std(r)`，另有零門檻下行波動的 Sortino。
v10 加入的是觀測訓練帳戶的最大回撤限制；降低 L 並不保證 Sharpe 或 Sortino
同步提高。MDD 取決於整條路徑的峰谷，標準差則取決於每一天的波動。

還有兩個容易誤判的改善方向：

1. 把 loss 改成「策略 log return 減 benchmark log return」，若 benchmark 不依賴
   模型參數，只是加上一個常數，梯度完全不變，不會因此更會超越 benchmark。
2. 若只是把所有日 log return 乘同一正常數，Sharpe 不變。實際槓桿還會改變費用、
   複利及離散成交，不能把拉高槓桿當成提高預測能力。

成長最大化與回撤控制應分開定義，這也符合
[Busseti、Ryu、Boyd 的風險限制 Kelly 研究](https://web.stanford.edu/~boyd/papers/kelly.html)。
但該文的機率限制、初始財富 drawdown 與分布假設不同於本專案的歷史峰谷 MDD；
不能借用它的保證來宣稱本模型未來一定不超標。

## 2. 第一優先：候選集合確實不完整

v10 第 38 輪停止時：

| 項目 | 實測 |
|---|---:|
| 更新前訓練 loss | -0.3572666940 |
| 訓練 MDD 幅度 | 28.7496965% |
| 訓練 benchmark MDD 上限 | 28.7519023% |
| 剩餘空間 | 0.0022058 個百分點 |
| 候選數 | 11 |
| 原始 Adam 步長倍率 | 只試 1 |
| 風險切線步長倍率 | 1 到 1/256，共 9 個 |
| 內側方向步長倍率 | 只試 1 |

9 個候選因回撤超標被拒；最後兩個候選的回撤其實合格，但 loss 變差：

| 切線倍率 | MDD 幅度 | loss 相對更新前的變化 | 拒絕原因 |
|---|---:|---:|---|
| 1/128 | 28.7321095% | +0.0000254366 | loss |
| 1/256 | 28.7435471% | +0.0000795071 | loss |

因此 `optimizer_stop.json` 的 `no_feasible_policy_step` 應理解為「已嘗試的候選
沒有同時通過兩項要求」，不能理解為不存在風險可行的點，也不能視為收斂證明。

### 可手算且已執行的反例

考慮參數 `(x,y)`，起點 `(1,0)`、loss `-y`，風險限制 `x²+y² <= 1`。
用兩組 Adam 學習率構造參數位移 `a=(0.1,1)`，精確風險法向量為 `(1,0)`。

- 切線方向為 `(0,1)`：任何正步長都走出圓形可行集合。
- 內側方向為 `(-0.1,1)`：完整一步的平方半徑是 `1.81`，也不合格。
- 內側方向乘 `1/8`：得到 `(0.9875,0.125)`，平方半徑為 `0.99078125`；
  loss 從 `0` 降到 `-0.125`，對應測試 MDD 幅度 **19.815625% < 20%**。

現行 `ExactPolicyStep.resolve()` 的 11 次搜尋仍全部拒絕。這在光滑、精確梯度的
問題上即可重現，所以不能全部歸因於期貨口數、BF16 或市場資料。
反例證明搜尋集合有缺口；它沒有證明補齊後的期貨策略一定更好。

### 建議的最小 v11 候選

保留 v10 原有候選優先順序；僅在整組候選全部失敗時，補試被省略的原始 Adam
與內側方向縮步。沿用既有 `1/2, ..., 1/256`，逐一用完整訓練帳戶檢查，保留
不違約、原回撤上限及 loss 不惡化要求。這樣有機會保留 v10 原本的學習前綴，
把額外工作集中在真正停滯的輪次。

不新增模型參數或風險懲罰權重。仍屬搜尋語意改變，須使用新訓練 fingerprint
和新輸出根目錄，不能接續舊 Adam 狀態冒充同一實驗。
紀錄應補足各方向被評估／未評估的倍率、拒絕原因、參數位移、輸出與實際口數
是否改變；窮盡後的原因宜標為 `candidate_search_exhausted`。

## 3. 第二優先：訓練與檢查使用同一參數，數值結果仍有差距

第 38 輪的訓練 loss 是更新前完整軌跡；`train_policy_loss_before` 是上一個已接受
參數的固定參數重播。因此可比較：

| 同一參數、同一訓練期間 | loss |
|---|---:|
| 訓練流程 | -0.3597014844 |
| 固定參數檢查 | -0.3572666940 |
| 差額 | -0.0024347904 |

這約為 1/128 候選被拒的 loss 差額的 **95.7 倍**。不能用它放寬接受門檻，因為
固定參數候選檢查本身使用相同評估路徑；但它提示學習梯度與接受檢查未必對著
完全相同的數值決策邊界。

目前尚未隔離原因。需用相同 checkpoint、初始帳戶及所有訓練日期，逐層比對：

1. 先固定同一組模型輸出，對照訓練／評估帳戶的逐日整口數、淨值、費用及 loss。
   這能區分帳戶／聚合差異與模型前向差異。
2. 再比較 DDP 每 rank 訓練模型批次 64 與評估模型 chunk 16 的逐日原始 score、
   輸出權重及第一次整口數分歧；不要只比較最終 scalar。
3. 檢查 sample mask、尾端 padding、模式切換與編譯 kernel，然後才做精度對照。

現行程式是在 action head 完成後才呼叫 `.float()`。若 Linear 在 BF16 autocast
內完成，事後轉 FP32 無法恢復已捨去的有效位元。可測「骨幹保留 BF16、action
head 與輸出變換用 FP32」，但要一併確認 TF32 設定與逐日結果；目前沒有證明
這就是實際停滯的根因。[PyTorch 數值精度文件](https://docs.pytorch.org/docs/main/notes/numerical_accuracy.html)
也說明批次／切片計算不保證逐 bit 相同，這只是調查依據，不是本次因果證明。

## 4. 第三優先：確認學到的是可重複的擇時能力

從全部 163 日帳戶得到：

| 觀測 | 數值 |
|---|---:|
| 出現多頭整口部位的日數 | 163 / 163 |
| 出現空頭整口部位的日數 | 0 / 163 |
| 與 benchmark 的日 log return 相關係數 | 0.95897 |
| 含截距 OLS beta | 0.78109 |
| 日 log return 波動／benchmark 波動 | 0.81451 |
| 淨損益 | TWD 55,655,280 |
| 隔夜持倉損益合計 | TWD 48,891,050 |
| 開盤到結算、包含費用的剩餘損益 | TWD 6,764,256 |

兩段損益與總損益有 TWD 26 的差距，來源是保存的 FP32 帳戶欄位捨入，未把它
改寫成精確到元的歸因。隔夜部分約占淨損益 **87.8%**；這是既定部位路徑的
損益拆分，不能解讀成拿掉隔夜持倉仍會得到相同其他收益。

本期間的行為更接近動態多頭指數曝險。沒有空頭不代表程式有錯；不能為了表格
好看強迫模型放空。也不能單憑相關係數推論所有輸入特徵都無效。

在忽略非線性成本的局部近似下，策略日收益可寫成 `w_t * R_t - c_t`，其中 w
必須由當時可用資訊決定。期望收益包含 `E[w]E[R] + Cov(w,R) - E[c]`。
若要提升報酬和 Sharpe，真正值得驗證的是曝險與下一期報酬／風險的關係，以及
交易成本；只降低平均曝險並不等於取得新訊號。

下一輪先保持模型及資料契約，修正搜尋及數值一致性。確認改善可重複後，再
考慮 prior-only 波動、期限結構或風險單位的輸出表達；新增特徵／輸出單位都需
獨立的因果與 checkpoint 驗證。目前沒有足夠證據優先增加模型深度或強制多空。

## 5. 2026 領先很薄，2025 也未達到同樣的報酬要求

| 期間 | 策略累積報酬 | Benchmark 累積報酬 | 策略／Benchmark Sharpe |
|---|---:|---:|---:|
| 2025 驗證 | 22.38% | 28.92% | 1.064 / 1.049 |
| 2026 已觀察的 163 日 | 55.66% | 54.52% | 2.533 / 2.029 |

2025 報酬落後 **6.54 個百分點**。2026 領先 **1.14 個百分點**，相對期末財富
優勢則約 **0.737%**；這兩種分母不能混用。

以相同日期的策略／benchmark 報酬成對抽樣，保留區塊內連續順序，各做 10,000
次 circular block bootstrap，固定 seed=20260928：

| 區塊交易日數 | Sharpe 差值的 2.5%–97.5% 分位區間 |
|---|---:|
| 5 | -0.124 至 1.107 |
| 10 | -0.064 至 1.003 |
| 20 | -0.009 至 0.942 |

三者都包含零。若從保存路徑移除任一成對日期，共有 11 個日期的移除會使累積
報酬領先消失。這是影響度診斷；未重新模擬交易，不能把刪除日期當成策略結果。

這些是固定已選模型的描述性敏感度分析，沒有消除研究選擇偏誤，也不是
studentized 檢定，更不是未來勝率。相關方法論可參考
[Ledoit、Wolf 的 Sharpe 時序推論研究](https://www.econ.uzh.ch/dam/jcr:ffffffff-961c-1dd9-0000-00007214c2bc/jef_2008pdf.pdf)。
反覆用同一測試期修改策略仍有選擇偏誤，參見
[Bailey 等人的回測過度擬合研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。

後續使用同一個合併候選做擴展 walk-forward，逐 fold 報告 benchmark 三項差值，
再用未參與選擇的新資料確認；不再以 2026 一次跨過門檻就宣稱穩定優於基準。

## 6. 計算效率應優先看完整帳戶檢查

排除前兩輪、取只有一個候選的 epoch：

| 計時 | 實測 |
|---|---:|
| 完整 epoch 最大 rank wall time 中位數 | 9.640 秒 |
| 訓練時間中位數 | 5.591 秒 |
| 參數檢查與準備時間中位數 | 3.551 秒 |
| 第 38 輪完整時間 | 50.432 秒 |
| 第 38 輪參數搜尋時間 | 44.400 秒 |

接近風險邊界時，額外搜尋占該輪約 **88.0%**。目前完整候選重播由 rank 0 執行，
另一個 rank 等待；可以研究分配候選或按連續日期分配模型前向後，再依原順序
重播單一帳戶。候選共享參數、編譯形狀、顯存與跨 rank 狀態必須另行驗證，不能
直接把循環並行化，也不能分段重置帳戶來換速度。

先記錄模型前向、帳戶重播、risk VJP、序列化／同步的獨立時間，再選擇要優化
哪一段。縮小搜尋重複工作或重用完全相同的候選才有機會保持學習語意。
單純改大 batch 同時會改變 TBPTT 截斷與數值形狀，不列為本輪第一優先。

## 7. 建議執行順序與驗收

1. 完成同 checkpoint 的 train/eval 逐日對照，定位首次分歧，不先放寬門檻。
2. 在新版本補齊既有方向的縮步，保留完整風險／loss 檢查及所有失敗候選。
3. 用一個合併設定實跑 Fold 14。只用訓練資料決定更新、2025 決定 checkpoint；
   除報酬風險外，記錄是否走過原 epoch 38、實際接受哪些新增方向及新增成本。
4. 用相同設定檢查其他年份，區分工程可學習性改善與策略泛化改善。

工程通過條件是：原 forward 逐日帳戶一致、因果和費稅不變、所有接受步驟仍合法、
新搜尋能通過反例且不重複空轉。策略通過條件則是新完整結果與跨年份證據；
這次分析尚未產生新模型績效。

本次驗證：既有 `test/test_exact_policy_step.py` **31 tests passed**；另執行
相同策略／benchmark 成對抽樣必須得到零差值、上述搜尋反例，以及禁止寫入
來源訓練根目錄的檢查，全部通過。來源完整生命週期及逐日帳戶稽核亦通過。
這些結果驗證分析工具與已知行為，不代表尚未實作的 v11 已通過測試。
