# FinLab／FinMind 歷史回補與增量排程

任務：`finlab-finmind-throughput-20261018`。2026-10-27 台北重新檢查，沿用原服務、
帳號鎖、共享流量帳本、持久收據與發布者，不增加另一份下載佇列。

## 先規劃再修改

工作分成「已到發布時間的追新」、「可取得的歷史缺口」、「來源未上架的探索」與
「剩餘配額校驗」。到期追新優先；不同供應商同時工作，同一帳號的各 lane 共用額度。
等來源的候選保持未完成，不能將等待計成下載完成，也不能每分鐘重掃完整市場。

本輪只讀清冊與修改前證據在
`artifacts/data_quality/finlab_finmind_scheduling_2026-10-27/`。
清冊本身沒有 provider 呼叫、佇列修改或歷史 Parquet 掃描。

1. FinLab 保留一般表格 → 分鐘 → 剩餘 tick 的順序。讓已知範圍的 tick 小缺口也走
   既有缺口佇列，避免較早未上架歷史擋住它們。分鐘與 tick 分別提供真實可執行量及
   下次重查時間；兩者都在等來源時，分鐘 timer 只讀 metadata。一般表格到期、
   使用者缺口請求、每日重置、發布重查與不確定證據仍交回正式下載器。
2. FinMind 維持已驗證的最大合法查詢單位、歷史階段順序及到期追新最高優先。
   檢查獨立 JSON 追新工作之間的 dataset 邊界是否無故排空整個 pool；可獨立發布的
   到期工作共用有限在途視窗，跨資料集樣本不得混成單一資料集的 ETA 容量。
   需 baseline 合併、物件傳輸或衍生的工作仍使用各自的既有處理器。
3. 驗證缺口優先、不提前發布、不重複 claim、錯誤恢復、共享額度與 ETA 身分。
   用原服務自然啟動或可證明無在途工作的邊界採用，核對新收據與實際程序身分。
4. 最後盤點發現資產交換選擇權 4 個舊項目停在 `not_entitled`，其中同一合法查詢
   現已用原 SponsorPro 帳號成功取得 495 列。舊錯誤沒有保留可區分原因的 403 訊息，
   不能據此認定永久無權限。修正未分類 403 的錯誤分類，沿用一小時冷卻及有限次
   失敗上限；只有明確的會員等級拒絕才封存為權限問題。明確重排支援 dataset 範圍，
   經原 worker lock 恢復這一項，不連帶重開其他無關的終止工作。
   同樣核實美股 `AEIS / 2026-10-12` 的舊 `provider_bad_request`：合法原查詢可取得
   338 列，再以原帳號鎖、精確 key 工作模式恢復這一筆。
5. 最後完整清冊另找到 133 個英股歷史項目停在 `retry_exhausted`；原 Markdown 摘要
   漏列這個狀態，先修正清冊，再以原正式 worker 重排。讀回發現有些非空的完整範圍
   回應實際只有近期資料，不能據此刪除已驗證的舊觀測。日資料合併契約升至 v3：
   普通完整重查保留回應未包含的已驗證歷史，同日以新回應為準，並記錄舊 SHA 與
   沿用筆數；有明確 correction scope 時仍依該範圍替換。從既存不可變原檔恢復已縮短
   的 current head，不再呼叫 API 取得本機原本就有的資料。

## 修改前觀察

- FinLab 一般表格 1,352 項：1,351 項已有資料，另 1 項來源空值；兩個分類字串欄位
  另外列為 metadata，不混成數值特徵。帳號取樣剩餘 4,730.525／5,000 MB。
- 最近四輪分鐘／tick pass 都是零請求；單次仍花約 17–60 秒。市場狀態只提供分鐘
  的等待時間，tick 則因剩餘候選巨大被誤當成隨時可執行。已知 tick 範圍還有 15 個
  未測候選，須先真正查詢，不能用「來源等待」一律壓掉。
- FinMind 為 SponsorPro，實際帳號上限 20,000 次／小時。106 個獨立資料集；大量
  剩餘為美股分鐘約 2,004 萬股票日候選，另兩項台股指標等待來源。這是搜尋工作量，
  並非已證明每個候選都有資料。既有來源證據顯示美股分鐘不能合併成多日／全市場請求。
- 期貨／選擇權最後結算價按官方週一至五每三小時追新；不能因歷史末日較舊就停抓。
  JSON pool 已有 16 個下載 slot、2 個發布 slot，但相鄰獨立到期資料集仍會先排空再切換。

## 驗證與採用

已套用原服務。FinLab 以 timer 自然啟動採用 acquisition policy v15；FinMind JSON
pipeline 採用 v17。第一次 FinMind 交接在 2026-10-27 01:28:56 台北，重新確認凍結後的
準備階段、兩份在途 claim 表皆為 0，再結束該 Python generation 並由原 unit 恢復。
永豐交易／報價及 FinMind 其他 lane 的程序身分沒有因此改變。

實作修正：

- FinLab 已知 tick 缺口走與分鐘同一種有限缺口選擇器；重試查詢先排除本輪額度已耗盡
  的古老探索，再套 SQL LIMIT，避免最近的可取得工作被擠掉。pipeline 每輪可使用既有
  1,024／2,048 個 tick／分鐘工作量，不再每 32 次請求重新準備全市場；在途數仍受原 pool
  限制，配額、開盤保護、到期追新和真實失敗時鐘仍逐次檢查。
- 分鐘、tick 都輸出可執行數與下一次來源重查時間。只有兩者都在等來源、收據與政策
  同期有效、日曆與商品來源 metadata 身分完全相同時，minute timer 才省略重型掃描。
  證據未知、檔案替換、一般資料到期、catalog 到期與流量重置仍會喚醒原下載器。
  這個 idle 分支有完整離線測試；本輪正式服務仍有實際工作，尚未以自然閒置週期驗收它。
- FinMind 獨立的到期 JSON 工作可跨 dataset 共用原有限 pool，原 selector 的優先序與
  claim 仍是唯一權威。歷史不同階段、baseline 合併、整日物件與衍生任務維持原處理器。
  混合資料集的批次不作單一資料集的 ETA 容量樣本，新版本也不混用舊配置樣本。
- HTTP 與 JSON error status 共用分類器；未分類 403 保留一小時冷卻及原本最多五次
  連續失敗限制，明確會員等級、token、IP 封鎖與限流則各自處理。明確人工重排可限縮
  dataset；資料與過去錯誤證據保留。4 個資產交換選擇權項目已實際恢復，659 列均讀回
  核對，原 Parquet 雜湊不變，下一次增量排程已恢復。另補回 AEIS 的 338 列舊分鐘資料。
  單筆走原序列下載路徑，驗收曾誤要求平行批次才有的欄位；原失敗證據保留，另由新程序
  以序列收據、完整檔案 SHA、筆數、股票和日期完成讀回，沒有為修正驗收再發 API 請求。
- 清冊 Markdown 也列出重試耗盡，不再因排程請求數為零而漏列。133 個英股舊項目
  經合法原查詢恢復，部分完整範圍回應卻只有近期資料；這不構成歷史刪除證明。
  合併 v3 保留未被新回應涵蓋的已驗證觀測，記錄沿用筆數、baseline SHA 及非完整性
  標記，同日採新來源值；明確更正仍可替換。已縮短的 head 另從原不可變檔案經正式
  publisher 恢復，全程無 API 呼叫，並由新程序讀回全部 133 個 head 與其增量時間。
  02:22:48 台北完成恢復：舊歷史 311,539 列與新回應合併後為 313,072 列；
  272,444 列舊觀測未被短回應涵蓋，仍保留於有效 head。新回應重複日期以新值為準，
  所有恢復前的不可變 Parquet 雜湊不變。永豐交易與報價、FinMind 其他 lane 身分不變。
