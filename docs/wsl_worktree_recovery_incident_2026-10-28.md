# WSL 工作樹整理事故與復原範圍（2026-10-28）

## 事故

整理 `/root` 下的 StockAgent 工作樹時，搬移工具的 Git 命令函式把正式儲存庫綁定成預設工作目錄。隔離測試替換了變數，卻沒有替換已綁定的預設值；測試因此對正式 Git 登記操作，把 19 個有未提交狀態的工作樹移入測試暫存目錄。測試結束後，暫存目錄連同這 19 個工作樹一起被刪除。這是本次整理操作造成的錯誤，不是使用者操作造成的。

主要工作樹 `/root/stockAgent` 沒有被搬移；事故操作沒有針對當沖帳本或服務。搬移工具已停用，不得再執行。原始工作樹名稱、搬移後 Git 登記與復原過程的固定證據保存在 `artifacts/operations/storage-single-authority-20261025/worktree-incident-20261028/`。這份紀錄不得作為刪除任何備份的授權。

## 已完成的復原與驗證

- 從 `/root/stockAgent-github-sync-20261015.LTXWb1/` 的 2026-10-15 備份，將 19 個工作樹重建至 `artifacts/operations/storage-single-authority-20261025/worktree-incident-20261028/recovered-snapshot-20261015/`，並修復 Git 工作樹登記。
- 19 個工作樹均核對原 HEAD 與原 index；備份列示的 3,720 個檔案均檢查 SHA-256，並檢查符號連結及原先不存在的項目。重建後 Git 狀態與 **2026-10-15 備份狀態**一致。
- 事故前各工作樹的 Git 變更項目數與復原後數量一致，但只有數量一致，並不能證明 10 月 15 日以後的檔案內容未改變。
- 驗證腳本曾刷新 index 的 stat cache；已根據事故前保存的 index bytes 還原，保留刷新前後證據，並核對 Git index 的語意。後續唯讀 Git 核對應設 `GIT_OPTIONAL_LOCKS=0`，避免再次刷新 index。

機器可讀證據分別為 `restore-snapshot-20261015.json`、`restore-original-indexes.json` 和 `reattach-snapshot-20261015.json`；同目錄的 `git-worktrees-metadata-before-recovery/` 保存修復前管理資料。

## 尚未證明的部分

目前沒有事故發生前每個工作樹的完整內容雜湊清冊，無法證明 2026-10-15 之後的未提交修改或 Git 忽略檔案已完整復原。事故前、復原後的磁碟配置量不同；這個差額不能解釋成資料損失量，也不能算作成功清理的空間。

保留所有現有恢復備份。應繼續查詢 lab203／NAS 或其他機器是否有 **比 2026-10-15 新**、能識別原工作樹名稱及檔案雜湊的副本；找到後先以獨立位置還原與逐檔對帳，不覆蓋現有快照。若沒有來源副本，再逐項記錄無法確認或無法復原的範圍。現階段不能宣稱所有內容已找回。

曾對運行中的 WSL ext4 嘗試唯讀列出已刪 inode，但工具無法開啟當時的配置位圖；這不構成檔案系統損壞證明，也不能證明檔案可或不可復原。未進行離線修復、卸載或其他可能中斷服務的動作。

## 防止重演

涉及搬移、刪除與自動清理的測試必須顯式注入測試儲存庫、限定可操作根目錄，並在執行任何寫入前拒絕正式路徑；不可依賴事後替換會被函式預設值捕獲的全域變數。任何搬移都須保留原始路徑、精確清冊及可獨立還原證據，測試失敗不得清除正式資料。
