# FinMind 全域三情境完成時間

## 範圍與驗證

這裡的「全域」是同一 FinMind 帳戶下 free、complement、sponsor 的去重責任佇列，
不是永豐、FinLab 等不同來源的聯合完成時間。網頁沿用現有 FinMind 面板：
`/finmind/` 的下載進度區。三情境顯示耗時、台北完成日期、請求數、速度與排除項。

## 計算契約

1. 沿用 105 資料集責任清冊；同一資料的舊 owner、停用新聞、非交易日與無觀測日期不重複計數。
2. 沿用已驗證合批契約及資料庫中學到的回應限制；已發出的請求不再次扣未來配額。
3. 帳戶限額取每分鐘官方觀測，非把三個 worker 的額度相加。
   目前觀測為 6,000 次／小時；現行 pacing 為 `3600 / (3600/limit + 0.01)`。
   使用官方 [user_info 用量端點](https://finmind.github.io/api_usage_count/)，不從方案名稱硬編碼額度。
4. 最快用當前合批請求／可用 pacing；中間用近 24 小時完整且活躍 15 分鐘窗的 P50 發出速率；
   保守用未合批請求／P10。三者均扣除當次追新預留，保守情境另計已知冷卻等待。
5. 工時轉日曆時間時沿用下載器交易日判定與 08:20–09:10 開盤保護。
   上述取樣 09/27、09/28 均判定休市，沒有平白追加保護等待。
6. 這是「請求成功、持續運作、校驗准入、在途／衍生能及時完成」的條件式估算。
   Request starts 不是成功完成事件；現有記錄不足以估算成功率、回應處理尾端或統計信賴區間。
   次要校驗需等跨來源必要工作通過准入；阻塞、未知、未排程絕不視作完成。
7. 真正最壞情況沒有有限上界。停機、失敗重試、新發現商品與額外配額消耗都可能延長。

## 更新、效能與故障

- `downloader/finmind_eta_work.py`：只讀 queue/status，不掃 Parquet、不呼叫資料 API。
- `downloader/finmind_eta_telemetry.py`：共用流量及 worker 觀測，只讀 SQLite 快照。
- `downloader/finmind_eta.py`：純估算／日曆轉換；輸出本機 `data_finmind/eta_status.json`。
- `scripts/snapshot_finmind_quota.py`：既有每分鐘 quota observer 順便更新估算。
  首次以 `--eta-only` 產生本機快照後啟用；不增加另一個資料 API 輪詢器。
- 總估算實測約 1.45 秒／次，每分鐘一次；公網只讀精簡快照，不因多人開網頁重算。
- 公網 ETA 快照投影單次約 2.1 ms（重複 100 次平均，非整個 gateway 的耗時）。
  流量帳本首尾改索引 seek，避免每分鐘掃描全歷史；本機樣本合計約 0.054 ms。
- 5 分鐘沒有新估算即過期，隱藏舊數字；估算失敗保留舊證據讓其自然過期，不破壞成功的額度取樣。
- 未修改下載器任務、授權、限速、交易、訓練或冷庫資料。

手動只讀更新：

```bash
source scripts/runtime_env.sh
run_fintech_python -m scripts.snapshot_finmind_quota --eta-only
```
