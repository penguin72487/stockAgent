# 台灣盤後資料鏈的獨立性與驗收

股票分鐘 K、期貨歷史 Tick、期權即時行情、Top-200 即時五檔與日沖分鐘曲線不是同一個下載任務。各來源可以獨立落盤；跨來源的訓練／日沖曲線只有在其各自的來源收據通過後才可產生。

| 階段 | 啟動／資料邊界 | 安全條件 |
| --- | --- | --- |
| 股票分鐘 K 回補 | 最新**已完成且已公開**的股票交易日；盤後與離峰執行 | 不等待期貨或 Top-200 收據；仍受 Shioaji 帳號連線與流量限制，來源缺口保留缺失標記 |
| TXFR1 歷史 Tick | 官方期貨日曆新增交易日後，歷史服務自動喚醒 | 收據須對應確切期貨交易日；不能用股票日曆推定已發布 |
| 日沖分鐘曲線 | 完成的股票交易日 | 必須驗證該日 TXFR1 收據；缺少時寫 `waiting_source`，不補造基準價格或完成狀態 |
| 期權 Tick／BidAsk | 日／夜盤視窗 | 策略結算失敗只阻擋策略，不阻擋獨立行情擷取；不得用資料擷取成功宣稱交易策略安全 |
| Top-200 即時五檔 | 僅交易時段可擷取 | 連線超額時寫 `skipped`；逾收盤窗口亦寫 `skipped`。已錯過的即時五檔不能由盤後分鐘 K 重建 |
| TWSE／TPEx／TAIFEX 官方盤後發布群組 | 各資料集的實際發布與定時重試 | 收據的 `status` 是程序結果；`data_status` 才區分完整、尚待發布與資料不完整，不能把程序成功當作來源已齊 |

官方端明確回覆「查無資料」或已驗證交易日的空報表時，才可標為 `waiting_publication`；無效 JSON、429、逾時與解析錯誤是未驗證來源失敗，不能假稱資料尚未發布。下一個定時／來源事件重試仍需持續執行。

Shioaji 的上限是**每個 person ID 同時五條登入連線**，不是每組 API Key 五條；`api.login()` 才佔一格。此機器預留兩條股票常駐報價、三條夜盤 FOP 行情。14:31 至隔日 05:00:10（含夜盤啟動前）兩個低優先歷史服務不登入；05:00:10 後它們用同一個跨行程檔案鎖序列化，每次最多一條歷史登入。股票分鐘回補在可用離峰保留這一條歷史額度，再依正在運行的 FOP 行程數決定自己的 worker 數；不能用降低報價／期權保留數來假裝消除容量瓶頸。07:45–14:31 歷史查詢仍按即時服務保護窗暫停。`shioaji_connection_capacity`、`live_connection_reservation` 與 `history_login_slot_busy` 都是可觀測的等待原因，不等於下載完成。改變帳號、worker 數或實際連線使用時，須重新量測並調整此預留策略。

重啟後先查 `systemctl is-active` 與 `journalctl -u ... --since today`，再查 `artifacts/data_repair/shioaji_{minute_full,historical_market_data,futures_history}/` 的當次進度／摘要。夜盤歷史服務顯示 `active` 且等待到 05:00 是預期狀態；當日分鐘分區、歷史收據、期權策略啟動與行情擷取要分別驗證。服務行程存活不能證明永豐端連線或策略正常。若夜盤策略因未結算的 shadow futures hedge 而 `capture=data_only`，只代表擷取仍在跑；必須另行稽核策略帳本，不可自動清掉避險腿或把策略標成 ready。

公開 Shioaji 面板分開顯示行情擷取狀態、策略啟動狀態、股票分鐘的容量等待，以及 Top-200/HFT 是否追上最新官方股票交易日。`active`、已有舊 Parquet、或下游 systemd 執行成功，都不是當日完整性證明。

驗收時依序檢查服務日誌、當次下載收據與目標日期、來源稽核、分區檔案列數，再檢查下游曲線收據。不要從舊 `download_summary.json` 或過去交易日的 HFT 稽核推斷目前已追到最新。
