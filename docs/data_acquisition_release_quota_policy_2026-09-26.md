# 資料發布與配額排程契約（2026-09-26）

「資料所屬日」、「上游發布日」、「本機檢查日」與「下載完成日」是四種不同時間。`待追新` 只應指上游新版已觀測到，或已過有根據的發布邊界而可推測新版出現；單純超過 24／48 小時未查詢，不是發布證據。歷史分區尚未補齊仍屬回補缺口，不因最新期未到表定時間而消失。

面板的 `publication.expectation` 區分 `due_observed`、`due_inferred`、`not_due` 與 `unknown`，並保留推定依據與 UTC 邊界。`waiting_publication` 不計入待追新，也不宣稱資料已到最新；已知來源變更或越過有根據的發布邊界才進入 `catching_up`。來源檢查 timer 不是上游發布時間。台股分鐘線的盤後 14:45 邊界是可查時段的操作推測，不是永豐保證的發布 SLA；使用已驗證 TWSE 交易日曆跳過休市，日曆不可信時不預測。Crypto 僅 OKX、Bybit、Binance、連續參照行情使用 24/7 新鮮度推測；ETF、Dune、鏈上彙整及總經不因加密貨幣分類而自動視為 24/7 發布。
FinMind 固定交易日資料另記最後**已查分區**（包含供應商空回），以下一官方交易日與各資料集既有發布時段推算到期；最近嘗試時間即使只有幾分鐘前，也不能掩蓋新發布邊界已過。當期／剛結束的分區在預期時段查到空回會於 15 分鐘後重查，而非等整天；更早的歷史空回不進入這個密集探測。財報、公司事件等非固定交易日發布來源不套每日發布規則。

配額遵循每個**真實共享桶**獨立調度：不同供應商無共同限制時平行跑，同一帳號／IP／端點的工作共用限速器與冷卻。固定增量先於歷史回補；必要取得先於交叉校驗；無已發布資料不消耗下載配額進行無界重試。已發布後立即查詢，不附加任意數日安全延遲；空回覆或未上架仍保留失敗／待驗證狀態與下次探測，不能製造完成收據。

| 共享桶 | 現行容量依據 | 固定增量與背景分工 |
|---|---|---|
| FinMind 同一 token | `/v2/user_info` 實測 `api_request_limit_hour`、`user_count`，所有 Free／Complement／Sponsor 走同一 `finmind-v4-data` 限速器；本機 request ledger 補計觀測後請求 | Sponsor `priority=0` 本期任務即使背景額度已保留仍可派送；歷史任務只可使用 `官方剩餘 − 下一小時已排固定工作 − 另外兩條序列 worker 容量 − 目前在途數`。每次批次重新核對帳號；帳號用量或本機 ledger 不可信時背景停、增量不被背景閘門阻擋。Calendar、Master、Complement 本期及 Sponsor 本期／下一小時規律發布工作列入需求。這是防止歷史回補吃掉增量的預留，並非供應商授權外的額度擴張。 |
| FinLab 同一帳號 | SDK 的每日 MB 額度，台北 08:00 重置須以帳號用量確認 | 既有單鎖排程先精選一般鍵與未取得鍵，再輪到其他到期鍵，最後才是 Tick；一般預留 50 MB、Tick 額外預留 500 MB，均可由環境設定調整。不同鍵費用差距大，不能用鍵數換算保證所有鍵每天更新，也不能把 24 小時未檢查直接標為「待追新」。 |
| 永豐 Shioaji 同一 person_id | 官方行情查詢上限 50／10 秒，另有每日流量、連線與盤中歷史查詢限制；以 `api.usage()` 實測剩餘位元組 | 即時行情／交易優先；歷史查詢在開盤保護窗停止，分鐘資料交易日盤後 14:45 追補。盤中訂閱推播不以輪詢歷史 API 取代。 |
| TWSE／TPEx／MOPS 等公開端點 | 端點沒有統一的官方數字；共用來源主機限速與 WAF 冷卻，不宣稱「10 req/s」是官方上限 | 具名公告探測、盤前及盤後不同階段使用交易日／發布事件判斷；休市仍可能有公告，不可一律跳過。歷史大批量回補遇 WAF 須退讓。 |
| OKX／Bybit／Binance | 各交易所及其端點獨立官方權重桶；以回應 header／錯誤冷卻修正 | 24/7 尾端分鐘線優先，歷史分區與交叉驗證用同桶餘量；三交易所互不阻塞。其他未啟用場館不因這個策略自動新增。 |
| OpenBB、SEC、FRED 等 | OpenBB 依實際上游 provider 分桶；SEC 使用其明示公平使用上限，其他未知限額只採本機安全政策 | 現有 OpenBB provider executor 以每桶服務能力限制並行與預取。這只保護吞吐與記憶體，**不是**完整的公告日增量預留；未有來源級發布契約時保持發布未知，不宣稱已完成每一端點的配額分配。 |

待補的精確度邊界：FinLab 目錄鍵和多數 OpenBB 指標沒有逐鍵可驗證固定發布時刻；需蒐集供應商公告／版本收據，建立逐來源的 `expected_release_at_utc`，才可轉為自動 `due_inferred`。TAIFEX 應使用自己的交易日／夜盤日曆，不拿 TWSE 股市日曆冒充期貨日曆。完整歷史、最新批次、PIT 可用性與冷庫發版仍分別稽核。
FinMind 的本機 request ledger 無法觀察別台主機在兩次官方帳號取樣之間的用量；跨主機共用同一 token 時，須新增跨主機配額協調或只讓一台負責背景回補。上游 402／429 仍會觸發既有共享冷卻，不把本機餘量估計視作保證。
