## 第一筆失敗的精確原因

2022-03-02，2888 的標準契約 `DDF:202203`，最佳模型請求權重
0.0029248767532408237，成交 1 口，13:30 剩餘 1 口。

- 08:46 有進場容量。
- 13:20 沒有分鐘棒，現有模型無法建立該時點被動限價。
- 13:28、13:29 各成交 1 口，現行逐分鐘容量為 `floor(0.5 × volume)`，
  因此兩分鐘各為 0 口，不能跨分鐘累積小數容量成為一口。
- 精確帳戶將未清倉判定為執行契約失敗，之後部位為零。曲線中的約 −100%
  是這個失敗狀態的數值標記，**不是這一口已實現虧掉 TWD 10M**。

以相同已驗證分鐘 tape、整口 executor 與 v4 代理梯度重算：

| 請求 | 實際口數／殘倉 | 單日 log 報酬 | 對請求權重的代理導數 |
|---|---:|---:|---:|
| 實際權重 | 1／1 | −16.1180954，失敗標記 | −0.99814886 |
| 實際權重的一半 | 0／0 | 0 | −0.99814880 |
| 0 | 0／0 | 0 | 0 |

負號表示增加這筆多單的請求會降低代理效用，因此更新方向會縮倉。
即使已落在零口區間，代理仍考慮下一口的退出失敗並提供縮倉訊號。
這說明這一筆沒有梯度斷裂，卻不構成整個模型的泛化或下降方向保證。

相鄰整口代理與精確分段常數目標是不同函數。STE 研究也明確區分代理梯度
和真實目標梯度，並在特定簡化模型下要求合適的方向相關性；該理論不能直接
作為本交易帳戶的收斂證明。
[Bengio 等，2013](https://arxiv.org/abs/1308.3432)、
[Yin 等，ICLR 2019](https://arxiv.org/abs/1903.05662)。

選模又是另一層：244 日內一個失敗標記的年化 log loss 約
`-log(1e-7) × 252 / 244 = 16.64656`，而本次最佳驗證的年化 log gain
只有 0.0002668726，數值規模相差約 62,376 倍。這是**選模目標值**的比較，
不是說反向梯度被放大 62,376 倍。空手 loss=0 自然勝過驗證期失敗的候選。
v4 的特徵正規化沒有改變這些容量、整口門檻與選模條件。

另做了單筆、記憶體內的容量反事實：只把觀察到的市價退出棒改成 100%
容量，該口可以退出，但含成本 log 報酬約 −0.002073%。這不是新資料驗收，
不能作為全資料改用 100% 的理由；來源中零容量證明仍綁定原 50% 契約。
沒有修改設定、來源、成交價格或正式結果。
