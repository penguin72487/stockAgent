# 台股分鐘資料完整性與回補（2026-09-22）

範圍是本機 `data_tw_minute/shioaji_1m` 及衍生的
`data_tw_minute/research_dataset`，不是全專案所有資料集。永豐股票歷史行情
官方範圍自 2020-03-02 起。09:01 是 09:00:00–09:00:59 完成的右標記
K 棒；09:01–13:30 共 270 個時槽不是 270 筆「應有成交」。一般收盤集合
競價 13:26–13:29 通常沒有成交，其他時槽也可能沒有成交。

## 可驗證的完整性層級

1. 官方交易日及當時可交易標的：不能用現在的合約目錄倒推歷史上市狀態。
2. 來源下載：每個 chunk 的 receipt、Parquet SHA、來源缺口、合約不可得
   要分開列；空回應可能是額度或服務異常，不是「沒成交」的證明。
3. 研究分區：逐列比對來源 `symbol, ts, OHLC, Volume, Amount` 等原始
   欄位，驗證唯一鍵、價格、時鐘、日期、標籤和分區 SHA。
4. 真正逐筆成交完整性：須有獨立成交逐筆或交易所權威時槽證據。
   單靠分鐘 K 棒與其 receipt 不能證明這層。

`scripts/audit_tw_stock_minute_coverage.py` 的「缺分鐘」是物理時槽缺席，
不是下載失敗筆數。`scripts/reconcile_tw_stock_minute_day.py` 的
`source_rows_missing_from_derived` 才是可以從本機來源直接修的漏行。
`source_coverage_gap` 表示來源本身不足，不能把研究分區的逐列一致誤當
全市場完整。

## 本機證據

- 全歷史範圍不是只補 09:01 或近期交易日：下載器的起點是永豐可查股票
  K 棒第一日 2020-03-02，逐檔查到最新已完成交易日。現在以公開日檔
  有成交量的標的日對照來源收據，2020-03-02–2026-09-21 共
  3,273,055 組：3,197,086 組有來源、58 檔的 68 組有與目前日檔相符的
  `source_gap`、75,901 組屬於 127 檔目前查無永豐合約的標的。
  原收據另有 59 個缺日不在目前公開日檔的有量日期內，單列為
  `source_gap_outside_public_daily`，不可自動判成有成交漏抓或無成交。
  這 59 組屬於 43 檔，全部集中在 2020-10-26–2020-11-06；舊分鐘
  收據建立於 2026-08-04–08-06，當時列為應查而永豐分鐘查詢未回傳。
  2026-09-22 的公開逐檔日檔及由既有分鐘來源聚合的本機永豐日檔
  都沒有這 59 組日期；後者不是獨立的再次 API 查詢，
  因此可證實舊收據的期待日集合與目前日檔不同；舊收據沒有保存
  當時日檔雜湊與逐日期清單，尚不能從現有證據判定是上游歷史修訂、
  本地重建，或舊版選日邏輯造成。往後有缺口的新收據會記錄參照日檔
  SHA-256、當前期待日期及沿用的舊缺口日期，讓變更可以回溯。盤點的缺口 CSV
  現在逐筆保留它們；自動回補也會重查，不再用目前日檔缺列來略過。
  例如 006204 的 2020-10-20–11-17 舊收據記載 18 個應查有量日、
  其中 10/28 與 11/02 未回傳；目前同一日段日檔只有 16 個有量日。
  只有實際回傳且驗證通過的永豐分鐘 K 能消除來源缺口；空回應保留
  為未證實，不會補造成交或宣稱已完整。這 59 組單獨列示，不加進
  「目前公開日檔有量」的 3,275,367 組分母。
  相反方向也有 2,905 個永豐來源 manifest 已回傳、但不在目前公開日檔
  有量日期集合內的標的日；盤點另列
  `source_returned_outside_public_daily`，不因日檔缺列而抹掉來源。
- 2026-09-22 目前的公開日檔另有 2,312 檔各一組有量標的日尚未進入永豐
  終端來源目錄；其中新登錄 7812、7856。9/22 仍是待補，不是完成。
- `scripts/audit_shioaji_minute_history.py` 可重算全部 2020 年起的
  日級盤點；逐檔和缺日 CSV、SHA 及逐年分類保存在
  `artifacts/data_quality/shioaji_minute_history/`。回補服務在建立研究
  分區前要求整段歷史的標的日都可歸類；`classified_with_limits` 仍明示
  合約不可得與來源缺口，絕非「每根分鐘線都齊」或逐筆成交驗證。
  此盤點母體是目前 `data_tw_public/stocks/symbols.csv` 所登錄、且仍有
  公開日檔的股票／ETF；不能外推成「2020 年至今所有曾上市標的」已齊。

  K 棒查詢；若獨占官方 50 次／10 秒的帳號行情查詢額度，純請求排程

## 實作與操作

- 全歷史日級盤點（完全本機、零永豐 API 流量）：

  ```bash
  source scripts/runtime_env.sh
  run_fintech_python -m scripts.audit_shioaji_minute_history --end-date 2026-09-22
  ```

- 下載器行情額度遵守官方現行的 50 次／10 秒（帳號內共享 5 req/s），
  同時維持流量與連線守門；盤中 07:45–14:31 不跑歷史回補。
- `--retry-source-gaps --all-symbols` 僅重試有收據的缺失 symbol-day，
  不再重抓整個 29 天區塊；保留舊 K 棒，對相同時間但數值衝突的回應
  拒絕覆寫。即使舊缺口日期已從目前公開日檔消失，也保留並重試，
  不以目前日檔覆寫永豐來源狀態。單日 K 棒空回應不會做同一請求兩次；若啟用逐筆回補，
  會查當日實際逐筆成交並記錄原始資料 SHA，仍未取得就標 `source_gap`。
- 既有 `scripts/run_shioaji_minute_full_backfill.sh` 盤後下一輪自動進行
  來源缺口重試；成功完成全來源建構和稽核後記錄目標交易日，
  每個目標日最多自動重試一次，後續新交易日會再檢查尚未解決的缺口。
  要在同一目標日手動再試，設定 `SHIOAJI_MINUTE_RETRY_SOURCE_GAPS=1`
  後重跑既有服務。下一輪完成前，不得宣稱缺口已補齊。
- 單日唯讀對帳：

  ```bash
  source scripts/runtime_env.sh
  run_fintech_python -m scripts.reconcile_tw_stock_minute_day --trade-date 2026-02-25
  ```

- 只有 `derived_mismatch` 且來源有效時，盤後加 `--repair` 才會重建
  該日，將舊分區移到 `data_tw_minute/quarantine/` 後更新 receipt 和
  manifest；若會移除沒有來源證據的現有列、來源鍵重複或價格無效，
  一律拒絕。此操作不補造無成交 bar，不更動交易 ledger。
- `build_shioaji_tw_minute_dataset --symbols` 現在禁止覆寫已存在的
  全市場分區或 manifest；子集合實驗必須給全新的獨立 `--output-root`。

目前仍缺「全市場每筆成交皆可被獨立來源證實」的保證。對合約不可得、
永豐未回傳的舊日期、沒有權威逐筆歷史的分鐘，必須在訓練時以
缺漏遮罩／不可執行狀態處理，不能補零價或前值當成真實成交。
