# 當沖頁面帳本投影修復（2026-09-27）

## 範圍與結果

修復公開網頁的資料讀取、帳戶摘要與警示判定；不重算或修改交易帳本、不補造成交、不切換模型。四個啟用帳戶為 `tw_day_trade_100m`、`tw_day_trade_multi_basis`、`tw_day_trade_multi_basis_22`、`tw_day_trade_v8_annual_log_cash`。

最新已記錄交易日 2026-09-24 的四個帳戶均可讀取，成交摘要為兩個完整成交、兩個部分成交，而非先前錯誤顯示的三個零成交。四個策略各有 270 個右標分鐘點（09:01–13:30），合計 1,080 點。帳戶損益對帳差異各小於 0.01 元。

## 根因與修復

1. **同一天不一定是帳本末端的連續區段。** 新帳戶匯入整段歷史後，同一日期會分散在多段 append-only 帳本。舊 tail 捷徑讀到不同日期就停止，使舊帳戶被誤判為沒有訊號。改用既有、可增量更新的日期位元組索引讀取所有對應區段；未變動的索引仍可重用。
2. **傳輸分頁不能決定帳戶真相。** 公開端點限制 `marks` 回傳筆數，舊邏輯卻用該片段計算全天完成度與期末權益。現在先以所選日期的完整 marks/events 算摘要，再限制回傳陣列。未啟用帳戶仍被排除。
3. **首次訊號登記不是最終成交結果。** 週末歷史投影曾以最初的 `signal_registered` 覆蓋後續補成交。只有日期與 signal ID 同時吻合時，才採用已提交狀態的最終成交計數；禁止混入其他日期或其他訊號。
4. **NAV 對帳必須涵蓋全部現金流。** 摘要漏掉企業行動與持有成本，造成約 264,768.34 元的假差異。改成 `已實現 + 未實現 + 企業行動淨額 - 持有成本`，沿用 canonical account-performance 欄位，不重複加計應收／應付。
5. **可載入 checkpoint 不等於正常執行。** 原本的「全部正常」判定過於寬鬆。改成綜合訊號、成交、權益與該模式警示，顯示「無警示」比例。明確登記的融資融券研究殘倉保留研究警示；嚴格當沖或未知契約仍保留未平倉錯誤。回補模型沒有當時即時測速時明確揭露，不補造 09:00 延遲數字。
6. **取消篩選與請求逾時不可混為一談。** 瀏覽器讀取 response body 遭內部逾時中止時，也可能拋出 `AbortError`。訊號、持倉、事件與歷史載入，現在只有自己的篩選 controller 已取消時才靜默忽略；其他錯誤正常揭露，不再永遠顯示「讀取中」。8 項測試同時覆蓋逾時與真正取消。
