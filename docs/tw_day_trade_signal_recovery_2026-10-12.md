## 根因與共用修正

1. **來源回應不等於當日開盤價。** 初次僅 114／2,299 個有效開盤輸入；
   09:10 左右仍約 1,890／2,290，未達原本的 90% 門檻。多筆來源仍是 10/08。
   保留已驗收資料，缺漏繼續自動補抓，不輸出假空倉。
2. **唯讀稽核持有來源寫鎖。** 08:30 工作的昂貴模型安全稽核尚在執行時，
   整段維持 exclusive lease，訊號讀取正確拒絕進入。來源／衍生層寫入完成後，
   現改持 shared lease、重新核對衍生層，再跑唯讀稽核；最終仍以 exclusive
   revision fence 驗證來源沒有改版。不解除鎖或略過原子來源驗收。
3. **MIS 失敗被記成成功的空集合。** 保留每批失敗類型、HTTP 狀態及失敗數，
   沒有有效輸入不再標為 complete。已證實的失敗採 provider-local 有界重試，
   不取消其他來源成功值，也不新增全域速率限制。
4. **等待和晚到訊號被 UI 混淆。** 缺價／來源正在更新成為可重試的具名狀態，
   保留安全的數值覆蓋率；超過五分鐘的真實 scheduled signal 與同訊號引擎登帳
   仍納入測速。手動／無關回放維持原有排除規則。模型已發布、引擎尚未登帳
   與完全沒有訊號分開呈現；延遲恢復不能改成開盤 SLO 成功。
5. **不同分頁被當成沒有持倉。** 訊號和持倉各自分頁，不能以持倉第一頁缺少
   該股票推斷未成交。訊號 API 從既有 overlay，以交易日、模式、股票、原始
   signal ID 四項精確對應 canonical 持倉，附 `signal_ledger_valuation_v1` DTO。
   沿用同一個 `_safe_position` 損益計算與公網 position sanitizer，不另做帳務。
   估值變更更新快取 fingerprint，不重掃訊號歷史；不暴露 private IDs、路徑或
   憑證。缺少對應估值只能顯示未知，不能把有紀錄的紙上成交改寫成未成交。
   Snapshot 參考估值明確標註為非成交證據。
6. **即時頁面驗收誤用網路空閒。** SSE 不斷更新時，不一定有一秒完全空閒。
   稽核改等初始請求 cohort 完成、必需 status API 成功及兩個 paint opportunity；
   仍拒絕初始請求卡住、required status 失敗、JS／API 錯誤與排版溢出。
   不停止即時更新、停用 CSP 或強迫點擊來通過驗收。
7. **行情更新反覆重建同一歷史查詢。** 訊號快取原本跟著與模型決策無關的
   全域 quote/content revision 失效；首次歷史尚未完成時，新請求又重複建置。
   快取改依實際訊號來源、查詢、資金與預期模型列數判定；估值仍按精確 overlay
   更新。訊號與事件的同一查詢沿用既有 builder/cache validation 合併等待，
   不同查詢仍可平行。遞迴 projection fallback 使用 reentrant lease；另記錄
   `query_singleflight_wait`。固定來源測試要求結果完全相同、來源只讀一次，
   同時核對來源追加與 feature 變更仍失效。初次 15 秒 API 逾時證據保留；
   冷來源成本不能冒充熱查詢，也沒有移除歷史列、分鐘點或現有掃描缺口提示。
