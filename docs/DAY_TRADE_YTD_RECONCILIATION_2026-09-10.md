# 當沖網頁 YTD 與模型測試集差異對帳

## 1. 執行進度與結論

2026-09-10 00:22（Asia/Taipei）完成唯讀診斷，資料終點為 2026-09-09。沒有修改程式、設定、模型、成交、帳本，沒有重跑推論／回補或重啟服務。本文件是本次唯一新增的專案檔案。

落差不是單純網頁百分比公式或手續費。已確認三個實質差異：

1. **模型選股遮罩不同**：訓練先限定當日當沖資格；live／歷史訊號生成先在「仍存在且取得價格」的較大股票池分配，之後執行器才拒絕不合資格股票。對跨股票注意力與 projection-L1，這不是等價運算。v12 曾把全部權重分給不可當沖股票，造成整日零成交。
2. **下單本金沒有承接淨值**：網頁背後的 paper engine 每天用固定初始資金決定股數；訓練的日頻整股與 exact-minute 執行器都承接帳戶 NAV。權益有承接，但獲利沒有加入隔天下單本金，不能把兩者當成同一個複利策略。
3. **有訊號不等於有成交**：回補帳本有缺少 09:01 價格、低於一張、資格及賣先限制等拒絕。這些不是曲線顯示的小誤差，而是實際持倉與模型目標不同。

技能「指標差異診斷」與「資料品質檢核」用於對齊時間、單位、版本與分母，並以逐日成交對帳避免只憑圖形推測。依使用者指定，報告僅為 Markdown，不建立 notebook、HTML 或網站筆記。

## 5. 初始本金與複利不是同一件事

paper engine `stockagent/live/tw_day_trade_simulation.py:491` 與 actionable-symbol 預檢皆使用：

```text
shares = floor(abs(target_weight) * initial_capital / official_open / lot_size) * lot_size
```

日頻整股回測 `stockagent/backtest/tw_integer_execution.py:3404`、`:3455` 使用承接現金、應收、應付、退佣的 `nav_before_trade`；分鐘回測 `stockagent/backtest/tw_day_trade_minute.py:183` 等路徑使用 `nav_twd = capital0 * equity_scale` 並跨日承接 state。

所以不是「昨天結餘整筆消失」：四個帳戶的昨日收盤權益都有承接。真正差別是線上委託計算仍乘固定初始資金，而非承接的 sizing NAV。

只做數學去複利檢查，多基底 02/25–09/09 的保存回測日報酬，複利為 +344.2763%，將同一批 daily simple return 相加為 +152.0865%；兩者仍都遠高於帳戶 +26.7126%。因此複利是重要差異，但不是唯一原因。這項相加不是重新執行固定本金策略，整張取整、資金與容量會隨本金改變，不能宣稱 +152.0865% 就是修復後報酬。

## 7. 價格與出場敏感度：只作對帳，不作可交易回測

固定多基底**實際已成交的股票、股數、方向**，不新增漏單、不變更資金，按同一組淨費率做會計反事實：

| 02/25–09/09、固定實際數量 | 淨損益／初始資金 |
| --- | ---: |
| 改以官方 open 買入／放空、官方 close 平倉 | +32.750034% |
| 保留實際入場價、改以官方 close 平倉 | +37.046342% |
| 實際逐筆成交與出場帳本 | +26.712589% |

在這個固定數量的診斷中，實際入場價相對官方 open 並未造成整體拖累；出場路徑相對 close 對帳少約 10.3338 個百分點。這不是完整策略反事實，不把已成交選擇當作事前可知，也不宣稱可在那些官方價成交。它僅說明不能把數百個百分點全部歸因於「開盤晚一分鐘／價差」。實際帳本期間淨費用約占初始資金 16.2734%，訓練亦已含費用，不能再將這個總額全部算成兩端差額。

## 8. 修復次序與驗收邊界（本次未實作）

1. 統一訓練、歷史回補、開盤、盤中及盤後各自明示的模型可見 universe／feature clock。需要當日資格的可執行當沖訊號，資格遮罩必須在 model forward 前生效；不要在出場或擋單後重新分配其他股票來假裝等價。
2. 分離「初始資金」與「本日 sizing NAV／可用資金／交割狀態」，共用 canonical sizing；不能只把 UI 改成複利，也不能靠改顯示本金達成。
3. 對回補目標逐一驗收 09:01 來源與拒絕原因；分鐘點數完整與訊號可成交完整要分開。修復來源後仍須候選帳本、完整分鐘曲線驗證，才能經既有 promotion 流程替換。
4. 固定 checkpoint hash、資料 release、ordered symbols、feature window、遮罩、AMP／模型設定，以相同輸入逐日驗證 raw score → requested weight → 合法整股 → fills → NAV；先做訊號等價，再比較執行事件。
5. 將訓練原始測試快照、後續正式推論、integer／continuous 結果分開標示版本及期間；處理 v12 零成交日殘留舊 archive。

未完成上述受控重跑前，不能承諾網頁會達到原訓練報酬，更不能把不具資格的目標或缺失價格視為實際成交。
