# 舊當沖回放的 C → E → D 自動遷移

使用者選擇：確認沒有現行服務或研究使用的舊回放，依資料集封裝至 D 後回收 C 副本。當沖現行帳本、服務與研究固定的回滾資料不屬於此工作。

這個排程只登錄三個已檢查的舊回放，不把其他 `service_data/live` 目錄自動視為可刪除。各回放的來源路徑和既有 hot 路徑，每個成員是同一 inode 的兩個 hardlink；單刪一邊不會釋放該 inode 的空間。任何第三個 hardlink、不同的名稱集合、特殊檔、跨檔案系統、來源世代變化，均阻止回收。

1. 檢查既有服務設定、使用中程序及研究／恢復引用。保留完整來源，建立固定來源清冊並計算各檔案 SHA。
2. 沿用來源清冊封裝器在 E 按同一資料集、原相對路徑寫入有界順序封包。封裝來源時再核對原始 SHA，保留斷點及控制紀錄。
3. 沿用私人冷庫發布器把封包依序寫到 D，核對串流雜湊，提交固定 head。寫入需取得既有 D 共用鎖及通過 E／D 容量檢查。
4. 再檢查 D 固定 head、安裝 journal 及物件世代，取得原 artifact mutation owner，重新檢查程序與引用，才按已記錄的雙名稱逐檔回收 C；各次 unlink 前後保留可續跑的 journal。服務鎖檔及目錄根保留。
5. C 回收完成後，沿用既有 E 暫存清理器回收已發布的 E 封包；完成狀態要求 D 發布、C 雙名稱回收及 E 清理三者均有收據。

依使用者這次的快速遷移要求，正式批次沒有新增 D 獨立讀回、完整解壓測試或 NAS 接收作為前置條件；D 發布與來源串流雜湊也不代表 NAS 驗收。合成測試資料的還原僅用於測試軟體，不是正式回放的還原證明。磁碟容量或服務執行狀態都不是備份驗收證明。

正式作業由 `stockagent-offline-replay-pair-migration.timer` 啟動，每分鐘在前一輪結束後重試；長工作續用既有中斷紀錄。日盤優先權沿用台股交易日曆與有界工作機制，開盤保護時段不開始新工作。各資料集的失敗獨立記錄，下一個資料集仍可嘗試。狀態投影由全資料監控面板每分鐘觀測，顯示各自目前階段、工作量與可從取樣推算的階段 ETA；缺乏速度樣本或有阻礙時不虛構完成時間。

2026-11-09 約 22:53 台北時間，前兩組各 916 個檔案均已完成 D 發布、C 雙名稱回收與 E 暫存清理。第一組 4,134,874,756 bytes 封裝為 125,659,931 bytes，回收紀錄為 4,136,574,976 allocated bytes；第二組 4,133,997,354 bytes 封裝為 125,672,107 bytes，回收紀錄為 4,135,694,336 allocated bytes。兩組 D 封包共約 239.69 MiB，C 回收紀錄合計約 7.70 GiB。曾重新核對 D head、安裝 journal 與目標物件世代，沒有執行正式 D 解壓讀回。WSL 剩餘空間會受其他並行工作影響。

其後新增固定的舊盤後回放；兩份目錄的 1,171 個名稱相符，909 個檔案逐一為成對 hardlink，觀測時沒有現行服務、程序或研究設定引用。排程已自動完成：3,695,301,075 bytes 來源封裝為 113,240,720 bytes，記錄回收 3,696,988,160 allocated bytes，E 暫存清理完成。三組封包合計約 347.68 MiB、C 回收紀錄合計約 11.15 GiB。其餘命名相近但連結集合不完全相同的資料不在此批，保持原樣。

對 WSL 重啟時可能出現的裝置編號變動，續跑只接受原 C 根及雙目錄的固定 inode、可信 C 掛載與逐項世代仍相符的情況。這是合成測試中的裝置編號變化，不是宣稱已完成實機斷電或重啟演練。

此前清查的 238 個 E 舊冷庫物件約 50.49 GiB，依使用者選擇保留並繼續追查歸屬；它們不在這個排程內。既有 D 資料集重封裝與舊版本回收仍由原有隊列與鎖處理；此排程完成不代表整體 C／E／D 遷移已完成。
