## 起始快照的正確性問題（後續處置見下節）

- 冷備份仍 `degraded`。既有清單有 113 個 `tw-public` 歷史物件缺件；目前 current heads 完整，但舊 release 不能宣稱都可還原。本輪沒有改寫 hash、manifest 或狀態。
- `systemctl --failed` 有 4 個單元：每日註冊資料更新、舊的宏觀資料補抓、隔日沖歷史回放、臺灣官方發布原件更新。最後一項的央行頁數證據不足；隔日沖回放因前一 cohort 未平而拒絕，不能以虛構成交繞過。舊宏觀失敗點的 Polars schema 推斷在目前工作樹已改為全量推斷，但該舊單元未重跑驗收。
- 資料監控快照為 `critical`，518 個來源列中 67 個 `unable`、47 個 `catching_up`。這些是端點／資料狀態的混合計數，不能把服務 `active` 或 API 200 當成修復。

## 後續量測與修復順序

1. 先查各 failed 單元的來源回執與可重跑界線；隔日沖要核對原始成交／未平證據，央行頁面要確認實際官方分頁契約。
2. 對資料監控 `public_s` 做分段 CPU／I/O 測量，保留 30 秒資料新鮮度及所有 518 列，再消除重複掃描。
3. 在安全、已核對未平狀態的時窗啟用當沖既有的休市閒置降頻，量測程序 CPU 與開盤喚醒延遲；不可直接以測試函數通過推論 live 已生效。
4. 訓練目前沒有在跑。任何模型／訓練效能結論仍須依完整 fold、冷暖分開及精確結果對等重新量測。

## 00:46 後續修復與驗收

- 央行列表曾以 HTTP 200 傳回 802 位元組的上游錯誤頁，且被存為最新列表快取。現在先驗證來源與列表分頁，再保存原始內容；已保存的錯誤頁保留供稽核、但離線快取會跳過它。官方發布原件服務完整重跑成功；外匯存底 317 筆，貨幣供給 321 筆，台股公開特徵 9,597,024 列。貨幣供給 2000-06 仍缺原始值，不冒充完整歷史。
- Crypto ETF 的 SEC 連線被 `RemoteDisconnected` 中斷時原本不在有限重試集合內。修正後以 4 個 SEC worker 實際重跑，40 檔基金、48 個來源完成，失敗與阻擋皆 0。免費公開資料的先前失敗端點另有成功回執；舊整批每日工作仍保留原失敗日誌，未宣稱那次 3.7 小時工作成功。
- 隔日沖歷史在官方開盤價缺失時不再把前批未平當成整批致命錯誤；只跳過該日的新進場、保留原部位與缺價證據。142 個交易日已重跑、1,136 個開收盤權益事件和 33,716 筆反事實成交通過價格、整張、費稅、損益核對，並部署到看板。130 次新訊號因前批未平受阻，期末仍有 2 個舊部位未解決，`fit_for_funded_performance_comparison=false`；看板現顯示這兩個真實計數。
- 舊宏觀資料補抓的 schema 失敗已有後續成功資料與測試佐證；每日資料與舊宏觀資料兩個舊 failed 單元的 systemd 告警是在核對後清除。官方發布原件與隔日沖歷史單元本輪實際執行成功；最後 `systemctl --failed` 為 0。這只表示這些工作目前沒有 failed 狀態，不等於全系統資料完整。
- 定向測試批次分別 49 與 96 個通過，JavaScript 語法檢查通過；本機唯讀 gateway 的 health、當沖、隔日沖、TAIFEX、監控 API 均回 200。未執行全庫測試，也未用瀏覽器做視覺驗收或從外網驗證 IPv6。
