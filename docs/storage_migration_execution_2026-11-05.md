## 面板與估時

`stockagent-workspace-seed-observation.timer` 每分鐘對已登錄、持有原排他鎖的 rsync 3.2 以上工作要求原生進度，並校驗程序世代、來源與目的地。只記錄清單已檢查項目及本次傳送量；這些數值不代表資料已讀回、服務已切換、備份完成或可刪除。訊號及 PID 身分先用隔離副本測試，讀不到有效取樣時不填造進度。

面板依各自工作收據的近期計數推估目前步驟，並列工作量、速度、下一次排程檢查及阻擋；不同時長的工作不可直接把百分比相加。檔案數與位元組數同時存在時兩者均顯示，避免把大量小檔案完成誤認為資料量已完成。流程區彙整各階段已登錄、待處理及可估工作，已知的目前步驟時間不代表完整階段或全域完成時間。未啟動、尚無速度或受外部條件阻擋的部分保持待估，估計逾期後等待下一次真實觀測。

本輪實測原容量觀測曾花 79.10 秒，其中 Windows 容量觀測單次 64.07 秒，即使子程序設有逾時仍可能受 WSL／Windows interop 拖住。監控 watch 模式改為最多一個背景容量查詢，獨立發布其他每分鐘狀態；慢查詢期間保留容量的原始觀測時間，過期就標示過期，不把舊容量更新為現在。這不能保證 Windows 或遠端每分鐘一定回應，但不再讓單次慢查詢阻塞整個面板。

本機 WSL／E 及 C／D／E 掛載的 `statvfs` 另有獨立單一查詢，不等待 Windows 或 Vast。Windows 原生容量仍較優先，但比本機新量測落後逾一分鐘時會使用較新的掛載量測；此時不會把舊 VHD 配置數字附到新的時間，VHD 分攤改為未知直到原生查詢完成。

## 後續執行順序

1. 原 staging owner 完成期貨資料的讀回、兩端清冊及固定收據，排程再執行連結檢查與 E／D 差異比對；其間保留 C 原件。
2. 逐來源建立並驗證 writer、reader、掛載與重開機恢復契約，再交給原來源 owner 進行 E 路徑交接。尚未登錄的來源不得假設會自動切換。
3. 由原備份與回收 owner 對 D 的保留差異及可回收內容逐項對帳，恢復各管線實際所需空間；不得用清冊差異當成原值讀回或自行解除保留。
4. 對每個來源取得對應 D 獨立還原及要求的 NAS 收據，核對當前程序引用後才由原 owner 回收 C 原件。C VHDX 實體回收及 Windows 空間須再分開量測。

上述未完成的來源交接、D 可用容量及 NAS 就緒資料意味著目前無法可靠保證全域完成時刻；面板會在各 owner 開始提供可比取樣後逐步填入可估部分。
